# 随手报账 · Android 与 Windows

[English](README.en.md) | 中文

本地票据整理与报账工具：拍照或导入发票 → 离线识别 → 人工核对 → 日历管理 → 按费用种类导出合并 PDF + Excel。界面可切换中文 / 英文（英式英语），货币可选英镑（GBP）或欧元（EUR）。数据只保存在本机，无账号、无云同步，手机和电脑各自独立。

**使用方法见 [用户手册](docs/user-guide.md)**（安装、设置、添加与核对发票、日历与出差国家、额度、导出、备份）。

## 功能

- **语言与货币**：在设置里切换，重启后保留（手机点右上角设置按钮，电脑点左下角“设置”）。每张发票记录自己的货币，不做汇率换算；切换货币不影响已保存的发票，编辑时也可改单张发票的货币。合计按币种分开显示。
- **五类费用**：市内交通（地铁）、市外交通、出差餐补、办公用品、客户招待。
- **离线识别**：PP-OCRv6 引擎在本机识别日期、实付金额和商家（安卓同时使用 ML Kit，Windows 失败时回退 Tesseract）。识别不确定时不自动填写，提供可点选的候选；手动修改的内容不会被重新识别覆盖。金额按所选货币处理：选欧元时还能读懂 `1.234,56`、`12,50 €` 和 Summe、Total TTC、Totale 等欧洲票据用词；选英镑时不启用这些规则。票据只标另一种货币时会提示核对，不换算。
- **自动裁剪**：识别前按票据区域自动裁剪、透视矫正和转正（两端）。安卓还可在“裁剪 / 矫正”里拖动四角微调，导出 PDF 使用裁剪后的图像；Windows 的裁剪只用于识别，导出用原图。原件始终保留不变。
- **批量导入**：安卓可多选文件逐张核对，关闭后可续接；Windows 可拖入窗口任意位置，或复制微信图片后点“粘贴微信图片”。一个文件为一张发票，多页 PDF 为一张。
- **日历**：绿色出差、红色办公、蓝色休假，可批量标记日期范围，与费用种类相互独立。
- **出差国家**：在日历标记“出差”时选择国家和天数。英国每天 £50；其他欧洲大区国家按公司差旅标准的每日餐补，用欧元计算（如德国、法国、荷兰 €50，瑞士、北欧 €60，意大利、西班牙、波兰等 €40）。发票日期落在出差日时，货币自动改为该国货币，可以手动改回。
- **额度提醒**（只提示，不阻止保存或导出）：
  - 出差餐补：出差国家每日标准 × 连续出差天数，单日可超；换国家、办公、休假或未标记日会断开，跨月/跨年不断开。只统计与该国货币相同的餐补发票。
  - 市内交通：每个自然月 £150，只统计英镑发票；设置选欧元时不显示。
  - 低于额度时提示未使用金额，等于额度显示已用满，超过显示超额。
- **主界面合计**：可选统计时间（本月〔默认〕、上月、日历所选月份、今年、全部时间）和费用类别，选择在本机记住。
- **导出**：先选费用种类 → 日期范围 → 勾选发票，生成合并 PDF 和 Excel（明细 + 分类汇总，不含所在地列）。按日期排序，Excel 页码对应 PDF。文件名如 `2026-10-01至2026-10-31_出差餐补报账_发票合集.pdf`；市内交通按月份命名，如 `2026年10月_市内交通报账_明细汇总.xlsx`。文件名和 Excel 内容跟随语言，英文如 `2026-10-01_to_2026-10-31_Travel_Subsistence_Receipts.pdf`、`October_2026_Local_Travel_Summary.xlsx`。一次导出可以混合货币，Excel 每行标明货币，每种货币单独合计。只有已核对的发票能导出。
- **归档与回收站**：导出后可归档；从归档区删除才进入回收站，30 天内可恢复。
- **重复提示**：相同原件或日期、商家、金额都相同时提示疑似重复，由你决定是否保留。
- **备份**：两端都可导出 ZIP（原件 + 信息 + 日历）。Windows 可从 ZIP 合并恢复；安卓暂无一键恢复。两端备份格式不互通。

## 主要限制

- 识别结果必须人工核对；所在地手工填写。约 150 张真实票据测试中，日期、金额、商家三项全对约 61%。
- 安卓：单附件 50 MB，一张发票最多 30 个附件，单 PDF 最多 200 页，一次导出最多 200 页；合并 PDF 为图像页，不保留原 PDF 的可搜索文字和数字签名（原件仍完整保存）。
- Windows：单文件 50 MB，每批最多 100 个文件，一次导出最多 300 页，备份最多 250 MB。
- 不支持零金额、退款，也不支持英镑和欧元以外的货币。欧洲语言的月份名日期（如 `12. März 2026`）暂不识别，需手动填写。

## 从源码构建（Windows）

| 目的 | 运行 | 说明 |
| --- | --- | --- |
| 首次准备安卓工具链 | `build.cmd` | 下载 JDK 17、Gradle 8.13、Android SDK 36 到 `.tools/`，需接受 SDK 许可 |
| 安卓正式版 | `tools\build-release-android.cmd` | Java 测试、lint、签名 APK、16 KB 对齐检查，输出 `output\BaoZhang-<版本>.apk` |
| 安卓测试版 | `tools\build-apk-test.cmd` | 同上，输出到 `output\test\`，不覆盖正式版 |
| Windows 正式版 | `tools\build-release-desktop.cmd` | 自动获取 Node 22，安装依赖、构建、测试（含真实 OCR 冒烟测试）、打包安装版 Setup EXE 与 ZIP，并再测打包后的程序 |
| 两端一起 | `tools\build-release-all.cmd` | 依次运行上面两个正式版脚本 |
| 发布到 GitHub | `tools\publish-release.cmd` | 需先安装 GitHub CLI 并 `gh auth login`；核对哈希后上传为最新发布版 |

日志在 `output\`。Node 测试：`node --test tests/parser.test.cjs tests/parser-sync.test.cjs tests/i18n.test.cjs tests/version-label.test.cjs`；桌面开发命令见 [desktop/README.md](desktop/README.md)。

### 签名与数据安全

- 安卓覆盖更新必须使用原签名。`.tools/personal-release.p12` 和 `.tools/signing.properties` 请私下备份，**不要提交或上传**（已在 `.gitignore` 中排除）。
- 源码备份不等于手机里的发票数据；换手机或重装前先在应用里导出备份 ZIP。
- 运行时不联网：安卓已移除联网权限，Windows 拦截所有 HTTP/HTTPS 请求。
